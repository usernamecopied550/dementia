# Companion database — development snapshot

Source: five Supabase metadata CSV exports, 27 November 2026. Contains 9 tables, 50 columns, 33 constraints, 16 policies, 3 functions and 1 trigger. No row data or credentials included.

## Files
01–05 are ordered SQL reference scripts for a fresh Supabase project, not migrations to run on the existing project. They have not been executed or validated against a fresh database. Supabase-managed auth.users, roles and extensions schema must exist. Do not run on the live project.

## Reconstruction limitations
- Column export omitted identity attributes; bigint IDs without defaults are reconstructed as GENERATED BY DEFAULT AS IDENTITY. Verify actual identity mode and sequence settings.
- RLS enable flags, table/function grants, ownership, indexes outside constraints, storage buckets/policies and Auth/SMTP settings were not exported. RLS is enabled on all nine tables in the reconstruction; pairing revokes/grants are restored from the implementation discussion. Other grants require verification.
- Original CSV exports are included for comparison. No live database was modified.

## Security review before real patient data
- Medications currently has a public SELECT policy with USING (true), and no patient ownership column. Do not store real medication data until redesigned.
- Medication logs has no exported RLS policies; verify RLS and intended access.
- Linked profile policy exposes the full linked profile row.
- Pairing codes are retained indefinitely and unique across all historical codes; cleanup and stronger abuse protection remain outstanding. used_at represents both redemption and invalidation.
- Verify task completion dates, storage access and all grants; test unauthorized access, reused codes and duplicate pairing. Dashboard locks are not a security boundary.
- Auth trigger requires role and full_name metadata; configure email verification, redirect URLs and SMTP separately without committing secrets.
